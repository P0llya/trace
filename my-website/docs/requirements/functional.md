# Функциональные требования (Use Cases)

## UC-REG-01: Регистрация нового пользователя

| Атрибут | Значение |
|---------|----------|
| ID | UC-REG-01 |
| Акторы | Пользователь (новый), Система |
| Предусловия | Пользователь на главной странице, не авторизован |
| Постусловия | Создана запись пользователя, выполнен автоматический вход |

**Основной поток:**
1. Пользователь нажимает «Зарегистрироваться».
2. Система отображает форму: Email, Пароль, Подтверждение, Имя (опционально).
3. Пользователь заполняет и нажимает «Создать аккаунт».
4. Система проверяет email, совпадение паролей, уникальность.
5. Система создаёт учётную запись и авторизует.
6. Перенаправление в личное пространство.

**Исключения:**
- Некорректный email → сообщение об ошибке
- Пароли не совпадают → подсветка полей
- Email уже существует → предложение восстановить пароль

**Бизнес-правила:** пароль ≥8 символов; email уникален.

## UC-COL-02: Создание новой коллекции

| Атрибут | Значение |
|---------|----------|
| ID | UC-COL-02 |
| Акторы | Авторизованный пользователь |
| Предусловия | Пользователь в личном пространстве |
| Постусловия | Создана запись коллекции в БД |

**Основной поток:**
1. Пользователь нажимает «+ Создать коллекцию».
2. Система открывает форму: Название (обяз.), Описание (опц.), Обложка (опц.).
3. Пользователь заполняет и нажимает «Сохранить».
4. Система валидирует название (не пустое).
5. Система сохраняет коллекцию и привязывает к пользователю.
6. Перенаправление на страницу коллекции.

**Исключение:** Название не введено → ошибка «Название обязательно».

## UC-ART-03: Добавление артефакта в коллекцию

| Атрибут | Значение |
|---------|----------|
| ID | UC-ART-03 |
| Акторы | Авторизованный пользователь |
| Предусловия | Существует коллекция, пользователь на её странице |

**Основной поток:**
1. Пользователь нажимает «+ Добавить артефакт» или перетаскивает файлы.
2. Система открывает интерфейс загрузки.
3. Пользователь выбирает файл(ы) (JPG, PNG, GIF, TXT) или вводит цитату.
4. Система отображает прогресс загрузки.
5. Система сохраняет файл в S3, создаёт запись артефакта.
6. Система обновляет сетку артефактов.

**Исключения:**
- Неподдерживаемый формат → файл отклоняется
- Превышен лимит хранилища (1 ГБ для Free) → предложение Premium

**Бизнес-правила:** макс. размер файла 25 МБ; поддерживаемые форматы – JPG, PNG, GIF, TXT.

## UC-VIEW-04: Просмотр списка коллекций

| Атрибут | Значение |
|---------|----------|
| ID | UC-VIEW-04 |
| Акторы | Авторизованный пользователь |

**Основной поток:**
1. Пользователь переходит на дашборд.
2. Система загружает и отображает сетку коллекций (превью + название).
3. Пользователь кликает по коллекции для просмотра содержимого.

**Альтернатива:** Если коллекций нет → отображается пустое состояние с призывом создать первую коллекцию.
